# Budgero SEO audit

Audit date: September 4, 2026. Website source reviewed at `274ece2f`.

Search Console source: `budgero.app-Performance-on-Search-2026-09-05.zip`, Web search, September 3, 2025–September 2, 2026. Despite the archive filename, September 2 is the last observation. Production crawl completed September 4 at 21:37 UTC, with targeted historical URL checks afterward.

## Assessment

**Growth has stalled and search visibility is weakening, but clicks have declined modestly so far.** The latest 28 days produced 314 clicks, down 7.1% from 338. Impressions fell 6.6%; CTR remained almost unchanged. August versus July shows a larger 13.2% click decline, partly because July included an unusually strong first week.

The more concerning signal is the latest two weeks: impressions fell 24.6% against the preceding two weeks, while clicks fell 7.4%. Better aggregate CTR cushioned that loss. This deserves investigation now, even though traffic is still above May and June levels.

The strongest supported explanation is **less search exposure, with some deterioration in aggregate position**. The export cannot establish whether that reflects lower rankings for the same queries, lost query coverage, changing demand, or a different mix of searches. It also cannot identify the recently declining pages: its page and query tables are annual totals, not dated comparisons.

The website has several real weaknesses, especially internal linking, comparison evidence, and the blog canonical. None is proven to have caused the recent decline. There is no evidence from this crawl of a site-wide robots block, mass broken sitemap URLs, or missing server-rendered content.

### Limits that matter

- The daily file has 365 unique, consecutive dates. Total clicks are 1,825 and impressions 73,359. Device and country totals reconcile exactly to those figures.
- The query export contains 898 rows but only 846 clicks and 15,242 impressions. It exposes 46.4% of clicks and 20.8% of impressions. Omitted/anonymized query data makes it unsuitable for an exact brand/non-brand split.
- The exact query `budgero` contributed 659 clicks: **at least 36.1% of total clicks were branded**. Its 77.9% share of visible query clicks must not be presented as the branded share of all traffic.
- The page table totals 1,865 clicks and 94,023 impressions. Page and property aggregation differ in Search Console. Use the daily file for site totals; use page rows for URL comparisons, without forcing the two totals to match.
- The property includes subdomains. `budgero.app` accounts for 1,839 of 1,865 page-table clicks; other hosts account for 26. The daily file does not separate hosts.
- CTR above is total clicks divided by total impressions. Position is reconstructed by weighting the rounded daily positions by impressions, so it is approximate and sensitive to query mix.
- This is a Performance export. It contains no Page indexing, Google-selected canonical, Crawl stats, Core Web Vitals, Manual Actions, Security Issues, backlink, or conversion reports. It also lacks the previous summer needed to test annual summer seasonality.

These qualifications follow the distinction between report aggregation and query visibility in [Search Console's Performance documentation](https://support.google.com/webmasters/answer/7576553). Google's recommended diagnostic workflow also calls for page/query comparisons and indexing checks. [Traffic-drop guidance](https://developers.google.com/search/docs/monitor-debug/debugging-search-traffic-drops)

## 3. Confirmed technical findings

### Priority 1: Five landing pages have no incoming internal links in the crawl

The following sitemap pages had **zero incoming HTML anchor links from the successfully crawled website pages**:

- `/encrypted-budgeting`
- `/zero-based-budgeting`
- `/goodbudget-alternative`
- `/pocketguard-alternative`
- `/quicken-simplifi-alternative`

This is bounded to the crawl, not a claim about every external link or Google's entire discovery history. Source searches also found no contextual incoming links to these routes. Their sitemap inclusion can aid discovery, but visitors have no comparable browsing path to them.

**Fix:** Add relevant links where users need them. Link the Goodbudget, PocketGuard, and Simplifi entries in the main alternatives guide to their comparisons. Link the homepage's security explanation to the encryption page. Give the general zero-based budgeting guide a distinct introductory role and link it from suitable educational content. Keep the product-specific docs separate if the two pages serve different needs.

Also improve access to proven pages: the homepage links to the general Monarch comparison but not directly to the much more productive European page. Add a small, contextual route into international budgeting and self-hosting comparisons instead of listing every SEO page in the footer.

Evidence: [alternatives guide rendering](../../packages/website/src/app/best-ynab-alternatives/page.tsx), [homepage](../../packages/website/src/components/landing/LandingPage.tsx), [footer](../../packages/website/src/components/site-footer.tsx). Google's guidance is to use crawlable links and ensure important pages are linked from other pages. [Link best practices](https://developers.google.com/search/docs/crawling-indexing/links-crawlable)

### Priority 2: `/blog` canonicalizes to the homepage

Production `/blog` returns HTTP 200 with `rel="canonical"` pointing to `https://budgero.app`, not `/blog`. Its title is simply `Blog`. The root layout supplies the homepage canonical, and the blog index does not override it. The blog index is also absent from the sitemap.

**Fix:** Give `/blog` a self-canonical, a descriptive title such as `Budgeting Guides and Comparisons | Budgero`, and a useful description. Add it to the sitemap. Consider removing the root-level canonical default so future routes cannot silently inherit it; keep explicit canonicals on indexable routes.

This is a real defect, but `/blog` has only one recorded annual click. Fix it promptly as low-effort hygiene; do not promise that it will explain or reverse the overall decline. Google's selected canonical must be checked in URL Inspection.

Evidence: [blog metadata, line 10](../../packages/website/src/app/blog/page.tsx#L10), [root canonical, line 42](../../packages/website/src/app/layout.tsx#L42), [sitemap](../../packages/website/src/app/sitemap.ts). [Google canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)

### Priority 2: Sitemap modification dates reflect deployment rather than editorial changes

Of 52 sitemap entries, 43 report September 4 timestamps clustered within approximately 152 milliseconds. The implementation uses filesystem modification times and falls back to the current time when file access fails. Neither reliably records meaningful content changes in a production build.

**Fix:** Use explicit editorial update dates, a maintained route manifest, or a build step based on meaningful content revisions. Omit `lastmod` when no trustworthy date is available. Ensure a code-only rebuild does not mark unchanged articles as freshly updated.

Evidence: [sitemap helper, line 12](../../packages/website/src/app/sitemap.ts#L12). Google uses `lastmod` when it is consistently accurate; sitemap `priority` and `changefreq` are not productive optimization targets. [Sitemap documentation](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap)

### Priority 3: Retired URLs and subdomain indexing need deliberate handling

`/docs/budgero-core-vs-cloud` currently returns 404 after recording 1 click and 780 annual impressions. `core.budgero.app/` also returns 404 after 8 clicks and 140 impressions. Check whether an existing current page genuinely replaces each; if so, use a permanent redirect to that relevant replacement. Do not redirect every removed page to the homepage.

`my.budgero.app/` returns an app shell without a robots meta directive or an `X-Robots-Tag` in the tested response. Decide whether app/login URLs should appear in search. If they should not, make the intended exclusion explicit. A current `dev.budgero.app/` check returned a 502 with `noindex`; `demo` did not resolve. Those hosts have negligible exported search activity and do not explain the overall decline.

### What passed

- All 52 sitemap URLs returned HTTP 200 directly and had self-canonicals, allowing for equivalent trailing-slash formatting on the homepage.
- None of those 52 pages had a `noindex` directive in the tested response.
- `robots.txt` allows the website and disallows only `/api/`.
- Main page text and metadata are available in server-delivered HTML.
- `/free-ynab-alternative` and `/blog/budgero-vs-ynab` each return a single 308 redirect to `/vs-ynab`.
- `/budgeting-multiple-currencies` returns a single 308 to `/multi-currency-budgeting`. Old URLs are absent from the sitemap.
- HTTP redirects to HTTPS. The tested trailing-slash page variant redirects to its canonical URL.
- Unknown top-level and blog URLs returned actual 404 responses.
- JSON-LD parsed successfully on the crawled HTML pages. Parsing does not establish Google rich-result eligibility.

These are present-time HTTP checks, not historical uptime checks or proof of Google's indexing decisions. No field Core Web Vitals assessment was possible from this export.

## 4. Content and search-intent findings

### Priority 1: Make comparisons accurate and demonstrably researched

The main alternatives guide marks Actual Budget bank sync as unavailable (`bankSync: false`). Actual's official documentation describes optional bank integrations; availability and setup differ by provider. The correct comparison needs those qualifications, rather than an unconditional cross. [Local comparison data, line 65](../../packages/website/src/app/best-ynab-alternatives/page.tsx#L65), [Actual's bank integration documentation](https://actualbudget.org/docs/advanced/bank-sync/)

The Actual-vs-Budgero article contrasts Actual's mobile offering as `None (responsive web)` with Budgero's `PWA (installable)`. Actual also documents an installable PWA. Distinguish native apps from installable web apps consistently. [Local article](../../packages/website/content/blog/actual-budget-vs-budgero.mdx), [Actual's FAQ](https://actualbudget.org/docs/faq/)

The sampled comparison pages contain no external editorial source links for competitor assertions. The main guide includes a useful disclosure that Budgero is the author's product and acknowledges alternatives' strengths, but it does not substantiate its recommendations with original product screenshots, a test methodology, or reproducible comparison measurements.

**Fix the leading pages first:** include the person responsible, the actual review date, sources for current competitor facts, and evidence of hands-on use. Useful tests include importing a fixed sample of YNAB transactions, reconciling balances, running a EUR/GBP household example, and trying the same workflow offline. Publish the limits and failures as well as the successes. Recheck competitor pricing and country availability rather than merely changing the year in titles.

This is an editorial quality finding, not proof of an algorithmic penalty. Google's review guidance specifically recommends original evidence, useful measurements, and first-hand reasons for recommendations. [Review guidance](https://developers.google.com/search/docs/specialty/ecommerce/write-high-quality-reviews)

### Priority 1: Improve the answer on established pages before expanding coverage

For `/monarch-money-europe-alternative`, show what a European user can actually do: a worked multi-currency budget, a tested file-import example, limitations of manual/CSV operation, hosting details, and the migration path. Verify and cite Monarch's current country/currency support at the time of revision.

For `/ynab-alternative-europe`, make the bank-import experience explicit. Supporting a currency or CSV file is different from integrating with every bank. Show tested examples and describe unsupported formats honestly. The page has enough impressions to justify investigating its actual queries and snippets before changing its positioning.

For `/vs-ynab`, make the offer unmistakable: free self-hosting requires operating infrastructure; managed Cloud is paid after a trial. The current description already qualifies this, but the title's broad free-alternative framing should be tested against actual query intent. A possible title is `Budgero vs YNAB: Free Self-Hosting, $35/year Cloud`; revalidate pricing before use.

For the Firefly and self-hosted YNAB pages, add concrete migration and deployment evidence. These fit existing query demand better than a broad expansion into generic personal-finance articles.

### Priority 2: Resolve overlapping intent only when the data supports it

Potential overlaps include:

| Pages | Sensible separation to preserve |
|---|---|
| `/monarch-money-alternative` and `/blog/budgero-vs-monarch` | Commercial alternative versus detailed head-to-head evaluation |
| `/self-hostable` and `/self-hosted-ynab-alternative` | Deployment/product overview versus YNAB replacement and migration |
| `/best-ynab-alternatives` and `/vs-ynab` | Market-wide comparison versus Budgero/YNAB comparison |
| `/zero-based-budgeting` and `/docs/zero-based-budgeting` | Method explanation versus instructions inside Budgero |

The annual export does not contain query-to-page mappings over time, so **cannibalization is unproven**. Do not merge or redirect these just because their topics overlap. First check whether the same query alternates between URLs while their combined clicks weaken. If two pages truly serve the same need, combine the strongest content, retain the best-established URL, and redirect the retired page. Otherwise, clarify scope and link between them.

### Low-priority cleanup

Five blog pages render both the template H1 and an H1 inside the MDX body. Remove repeated title headings for clearer document structure when editing those posts. This is not a credible primary explanation for the decline.

Do not spend this recovery effort expanding FAQ schema. Google stopped showing FAQ rich results on May 7, 2026. Existing FAQs can remain useful to readers, but adding more markup is not a current Google rich-result opportunity. [Google's documentation update](https://developers.google.com/search/updates#may-2026)

## 5. Recommended work sequence

| Order | Work | Acceptance criteria |
|---|---|---|
| 1 | Obtain dated page/query comparisons and inspect key URLs | Know which URLs lost impressions/clicks, which queries changed, and whether Google selected the intended canonical |
| 2 | Fix blog canonical and add contextual links | `/blog` self-canonicalizes and enters the sitemap; the five orphan pages have useful incoming links; important international comparisons are easier to reach |
| 3 | Refresh the two Monarch pages, YNAB Europe, and the main alternatives guide | Correct sourced facts, actual review dates, original evidence, explicit limitations, and measurable migration examples |
| 4 | Correct sitemap dates; handle genuine retired-page replacements | Unchanged pages retain their dates across rebuilds; relevant replacement redirects work in one hop |
| 5 | Improve self-hosting and Firefly content, then assess overlap | Product-specific workflows and tested examples; consolidation only where query/page evidence supports it |
| 6 | Evaluate results after Google recrawls the changed pages | Compare completed 28-day periods for the same pages and query groups; assess search clicks and qualified trial starts together |

Record deployment dates and changed URLs. Avoid changing all titles, content, and URL mappings at once: it would make attribution harder. Do not promise a particular traffic increase from these fixes.

The repository added Umami on July 16 and changed trial attribution on July 17. Those analytics changes do not alter GSC click counts, but they complicate comparisons of sessions or conversions across that boundary. Keep Search Console acquisition trends separate from PostHog/Umami instrumentation effects, and verify landing-page-to-trial attribution before judging business impact.
